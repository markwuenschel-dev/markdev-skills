01 — Executive assessment

canonical child data · zero fabricated scores

Grade C at 67.9/100 with high confidence (87.2) and 73.4% weighted coverage.

The repository is mid-maturity in the precise sense the rubric means: controls exist almost everywhere and enforcement is inconsistent in a small number of identifiable places. Its declared suite is green in isolation (718 pytest, 201 JUnit, 111 vitest), its safety boundary is continuous across three languages, and its documentation is unusually self-critical. What holds it at C is that several load-bearing invariants are maintained by review rather than by machinery.

This assessment is bound to one immutable revision (f5ac818, clean tree) and three hash-verified owner artifacts, with a shared verification baseline executed in a detached worktree rather than in the working tree. Health grading, integrity scoring and architecture dispositions are recomputed from those artifacts by their own verifiers, not restated. The dominant finding is a convergence rather than a defect: this repository has three cross-language vocabularies, two of which are protected by tests that literally parse the other language's source, and one — the failure taxonomy that ADR 0003 exists to protect — which is protected by nothing. It is correct today; every one of its ten codes was enumerated against the Java switch and matched. It is correct because people have been careful, which is the level-2 condition the maturity scale names, and it is one added enum member away from reproducing the exact defect ADR 0003 was written to eliminate.

12 — Assessment status and next lifecycle

Tooling defect · not a repository finding

scripts/performance-receipt.js:58 sets cache.sei = startup.startup_mode, but FRESH_BASELINE is a valid MODE (line 8) and not a valid CACHE_STATE (line 10), so line 61 rejects the receipt the function just built. Every FRESH_BASELINE run of this skill therefore cannot produce a receipt through buildPerformanceReceipt. The receipt bound to this report was constructed directly in the same shape with cache.sei set to MISS, the semantically correct state for a fresh baseline, and validated against both validatePerformanceReceipt and assets/performance-receipt.schema.json. startup.mode still reads FRESH_BASELINE.

Envelope note · non-fatal

sei_assessment_ref was omitted from the child envelope: SEI emits sei.engineering-assessment@3, the RIA envelope contract defines the reference at @1, and SEI's own RUNTIME-CONTRACT.json declares @2. The field is optional, so this is not fatal; forging a reference that fails its own validator would have been.
