# codebase-integrity-audit-loop migrations

## 2.0.0 → 2.1.0 (runtime contract 2.1.0 → 2.2.0): RIA coverage receipt (composite-scoring-v3 §7.1, §6.4) — 2026-10-16

- **New, RIA mode only.** Under `--ria-envelope`, `assets/write-ledger.js` requires a top-level `coverage` receipt (`integrity.coverage@2`) and runs `assets/integrity-coverage.js` before storing the ledger. It fails with `FAIL-INTEGRITY-COVERAGE-INVALID` on a missing receipt, a missing mapped surface, a duplicate surface, an unresolved or cross-revision ref, a declared coverage number, a core surface marked `not-applicable`, `inspected` with weak evidence, or an invalid negative-claim receipt. Integrity-minted rows (`integrity:` ids) must carry `ria_dimensions`, `defect_class` and `ria_proof`. Verifier limitations (for example an adopted row without `lane_sources`) are returned as owner-return `warnings`.
- **Unchanged outside RIA mode.** Without an envelope the receipt stays optional and ledgers write exactly as before.
- **Source resolution and absence scope (§7.1 rules 4–5; Promotion A review 2026-10-16).** `verifyIntegrityCoverage` takes `resolveSource(path) -> {state}`. With it, every `path` ref (surfaces, `not_applicable` declarations, negative-claim `path`/`line` sources) must name a file present at the assessed revision. Without it the check is syntax-only and the result says `sources_verified: false`; RIA always supplies one and scores nothing from an unverified receipt. The writer stays syntax-only; RIA's consumption is the authority. A negative claim supports absence only if its path sources cover every path the applicable inspected or sampled surfaces record. Every exclusion must be a `surface:<id>`, a ledger row or a repository path that removes no recorded or graded path. Free-text exclusions cannot be checked, so they defeat absence. `assets/canonical-ria-ledger.json`'s security negative claim now lists the paths it searched.
- **Every ref resolves; recorded scope includes scope text (§7.1 rules 4–5; recheck 2026-10-17).** With `resolveSource`, refs of every kind must resolve. An `inventory` ref names an inventory file present at the assessed revision. A `claim` ref names a negative claim in the ledger. A `command` ref names a command in the bound verification baseline (new option `resolveCommand(id) -> boolean`; RIA passes the baseline's command ids). A `rationale` is prose, not a reference, and fails. For absence, an inspected or sampled surface's recorded scope is its `path` refs plus every token of its `scope` text that names a file present at the assessed revision, or a directory written with a trailing slash. The claim's path sources must cover all of it. A surface that records scope through an inventory, command or claim ref cannot be enumerated, so it defeats absence: cite the inventoried paths instead.
- **Scope text has a closed grammar (§7.1 rule 5; second recheck 2026-10-17).** This supersedes the token reading above. For absence, a surface's `scope` must be empty, `<surface_id> at the assessed revision` (the surface, enumerated by its path refs), or a list of repository file paths separated by commas, whitespace or `and`, each resolving to a file at the assessed revision. Any other text, such as prose, a quoted name, a directory or an unresolved path, is reported as unenumerable scope and defeats absence. Nothing is silently dropped.
- **Each inspected surface needs a file inventory (§7.1 rule 5; third recheck 2026-10-17).** For absence, every applicable inspected or sampled surface must list at least one file, as a `path` ref or a resolving file path in its `scope`. A surface that cites only candidates, with empty or surface-phrase scope, has an empty inventory. That is reported as unenumerable and withholds absence; it can no longer pass an empty-list comparison. One enumerated surface does not vouch for the others.
- **An inspected claim needs inspected surfaces (§7.3; fourth recheck 2026-10-17).** A negative claim asserts inspected coverage over the dimension's mapped surfaces, as Evidence Recon requires. So absence is supported only when every applicable surface it covers is itself `inspected`. A `sampled`, `inventory-only`, `uninspected` or `unavailable` applicable surface is reported as a contradiction and withholds absence. Sampling every surface cannot produce a 100. Non-core `not-applicable` surfaces are outside the applicable set and unaffected.
- **Diagnostic boundary named (SKILL.md; deployment reconciliation 2026-10-17).** The authority boundary now says that under exact authorization `production-flywheel` repairs a selected defect using `/adaptive-causal-debugging`, and that `/diagnosing-bugs-mwdev` is its deprecated compatibility alias. This carries forward the deploy source's local hand-off edit without restoring the old mutation-owning workflow.
- **`REPORT-SCORING.md` compatibility pointer (deployment reconciliation 2026-10-18).** The scoring spine moved to `shared/candidate-ledger-spine/REPORT-SCORING.md`. A short pointer at the old path keeps references to `codebase-integrity-audit-loop/REPORT-SCORING.md` resolving, from Flywheel, the plan contract, the swarm planner and the architecture fork in the deploy source. It restates nothing. (`MANIFEST.json` `files.report_scoring_compatibility`.)
- **Proof receipts.** A minted row's `reproduction` proof is admissible in RIA only when its `receipt_sha256` names a stored `ria.proof-receipt@1` (`<sha256>.json` under `.project-intelligence/assessments/integrity/receipts/` or the RIA runtime root's `receipts/`) recording the same kind, binding, predicate, expected, actual and exit code. Containment (`ria_proof.containment`) needs a passing `prevention-check`/`runtime-guard` receipt.
- **Spine.** `coverage` is an optional top-level field of `shared/candidate-ledger-spine/candidate.schema.json` (spine version stays 3).
- **Readers.** RIA's composite v2 reads the same verifier output; nothing changes the reported v1 composite.
- **Fixtures.** RIA callers (`repository-improvement-assessment/scripts/test-support/ria-stock-adapter.js`, `scripts/owner-return.integration.test.js`) now use `assets/canonical-ria-ledger.json`; `shared/candidate-ledger-spine/canonical-ledger.json` stays the plain spine example.
