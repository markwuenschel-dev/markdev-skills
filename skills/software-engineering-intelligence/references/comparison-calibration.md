# Trend comparison and calibration

Read this reference only for an automatic or explicit canonical baseline, cache-reuse boundary, or heuristic backtest. SEI does not construct a health grade or turn a heuristic into a probability.

## Baseline comparison

Without `--baseline`, a first run publishes its ordinary immutable snapshot and records that the automatic baseline is established for a later compatible run. If no compatible SEI snapshot exists, the same run also records bounded Git-history context for the nearest significant first-parent change (merge commit, at least three changed files, or at least 100 lines of text churn). This context is orientation only: it has no prior SEI snapshot ID, cannot produce metric deltas, and is never presented as an asserted pull request. A later run against the same output root scans only the direct `snapshots/*.json` inventory. The scan is deterministic and fail-closed: at most 512 regular, non-symlink files, at most 32 MiB per snapshot, and at most 256 MiB across the complete bounded candidate inventory are considered. If the aggregate candidate-byte ceiling is exceeded, SEI establishes the current observation without reading candidates or selecting a partial inventory. Every candidate must validate against the canonical schema, survive canonical rematerialization with the same snapshot ID and filename, and match repository identity, schema, configuration, history root, collector states/versions, profile contracts, analyzer semantics, and at least one source-valid numeric metric. SEI selects the nearest strict Git ancestor, breaking an equal-topology tie by snapshot ID. Same-revision, descendant, divergent, corrupt, forged, drifted, missing, and over-bound inventories produce insufficient history while the current output still publishes.

Default repository identity is stable across clean clones: supported network origins are normalized without protocol, user information, default ports, trailing slash, or `.git`; host case is normalized, while path case is normalized only for known case-insensitive forges. A local, `file:` or missing origin binds identity to the sorted full root commit IDs, never to the local checkout path. A configured `repository_id` always wins.

Use `--baseline <canonical-snapshot-or-ref.json>` only with a complete canonical snapshot or its closed hash-bound reference. The runner reads that caller-selected file, validates it, materializes it again, and rejects any identity or digest mismatch before collection. An explicit baseline takes precedence and disables automatic snapshot discovery for that run.

Comparison is limited to matching repository identity, schema/configuration binding, collector/analyzer versions and states, profile contracts, history boundary semantics, metric identity, and source evidence. Any incompatible or missing condition produces `incomparable` or `insufficient-history`, not an invented delta. Without a directional interpretation contract, the receipt emits `stable`, `incomparable`, `insufficient-history`, or a null directional label alongside factual compatibility; it does not invent improving/worsening or significance.

Compatibility and direction are separate facts. A bound metric records the baseline kind, snapshot and repository revision, prior value, factual delta, and confidence bounded by the lower prior/current measurement confidence. The offline report may render repository-scope `before -> after`, magnitude, delta, unit, confidence, baseline source/revision, and comparability coverage. It must also say `direction/significance unassigned — no directional interpretation contract`. When canonical snapshots have evidence-bound factual deltas but no declared directional interpretation contract, the receipt sets `compatibility: "comparable"`, `direction: "unassigned"`, and `label: null`. `null` means that no directional presentation label is emitted; it is not an `incomparable` claim, and it must not be rendered as a sixth label. A caller may inspect the metric deltas and compatibility state, but may not infer `improving`, `worsening`, or significance. `stable` remains available only when the complete compatible comparison has zero deltas.

Cache reuse is independent of a baseline claim. It requires the exact newly collected canonical snapshot bytes and expected identity; a stale, altered, aliased, or incompatible cache artifact fails closed or is a miss. A baseline can never authorize reuse of an unbound cache entry.

## Honest heuristic backtests

`calibration.js` evaluates declared ranks against independently attested historical labels. Its labels and snapshot observation times are verified through a host-owned verifier/resolver outside caller JSON. A caller digest, `trusted` flag, arbitrary issue reference, or self-signed label is not calibration evidence.

The attestation binds the full canonical snapshot document (including `generated_at`), snapshot ID/revision/observation time, outcome subject/time, and immutable label artifact bytes. Training and holdout windows must not overlap; snapshot observation must precede its outcome, and training outcomes must precede holdout snapshot observations. Missing or unverifiable trust evidence produces `unverifiable` or `insufficient_data`.

Available receipts report the inspectable combined heuristic and naive LOC, lexical-complexity, churn, and commit-frequency rank baselines. Precision at K, recall, lift, AUC, and calibration error appear only when the held-out data permits them. These remain heuristic performance receipts: they do not set a canonical risk model to calibrated/validated or emit a defect probability.
